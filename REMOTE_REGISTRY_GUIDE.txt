🐳 FINAL PRODUCTION DOCKER HUB REGISTRY & REMOTE SITE DEPLOYMENT MANUAL
================================================================================

[PHASE 1] IMAGE SIGNING & CLOUD PUSH (RUN ON LOCAL MACHINE)
--------------------------------------------------------------------------------
1. Navigate to your containerization folder:
   cd ~/repos/cool_demo/Google_Gemma/Gemma4/vla_docker

2. Log into your Docker Hub account over the CLI:
   docker login --username your_dockerhub_username

   (When prompted, enter your Docker Hub password or Personal Access Token)

3. Compile both optimized architecture layers simultaneously:
   DOCKER_BUILDKIT=0 docker compose build

4. Tag the built images to link with your personal Docker Hub namespace:
   docker tag jetson-gemma4-server:latest your_dockerhub_username/jetson-gemma4-server:latest
   docker tag jetson-gemma4-agent:latest your_dockerhub_username/jetson-gemma4-agent:latest

5. Push the finalized images to the global cloud hub registry:
   docker push your_dockerhub_username/jetson-gemma4-server:latest
   docker push your_dockerhub_username/jetson-gemma4-agent:latest


[PHASE 2] LIGHTWEIGHT PRODUCTION ORCHESTRATION FILE (SAVE ON REMOTE SITE)
--------------------------------------------------------------------------------
Save this exact text block as 'docker-compose.yml' on the remote system inside
a fresh deployment workspace directory. 

⚠️ CRITICAL: Replace 'your_dockerhub_username' with your actual namespace!

services:
  gemma-backend:
    image: your_dockerhub_username/jetson-gemma4-server:latest
    runtime: nvidia
    network_mode: "host"
    ipc: host
    ulimits:
      memlock: -1
      stack: 67108864
    volumes:
      - ~/models:/models
    command: >
      --model /models/gemma-4-E2B-it-Q4_K_M.gguf
      --mmproj /models/mmproj-gemma4-e2b-f16.gguf
      --port 8080
      --ctx-size 2048
      --parallel 1
      --flash-attn on
      --n-gpu-layers 99
    restart: unless-stopped

  vla-agent:
    image: your_dockerhub_username/jetson-gemma4-agent:latest
    network_mode: "host"
    ipc: host
    depends_on:
      - gemma-backend
    devices:
      - "/dev/video0:/dev/video0"
      - "/dev/snd:/dev/snd"
    volumes:
      - /run/user/1000/pulse:/run/user/1000/pulse
      - ~/.config/pulse/cookie:/root/.config/pulse/cookie
      - ~/.cache/huggingface:/root/.cache/huggingface
    environment:
      - PULSE_SERVER=unix:/run/user/1000/pulse/native
      - MIC_DEVICE=plughw:0,0
      - SPK_DEVICE=bluez_sink.A0_E9_DB_00_B1_10.a2dp_sink
    stdin_open: true
    tty: true


[PHASE 3] CLEAN PRODUCTION INITIALIZATION (RUN ON THE REMOTE HARDWARE)
--------------------------------------------------------------------------------
Execute these fast terminal blocks on any brand-new remote system to start up:

1. Setup the target weight filesystem layout:
   mkdir -p ~/models

2. Move your 'gemma-4-E2B-it-Q4_K_M.gguf' and 'mmproj-gemma4-e2b-f16.gguf' model
   files directly into the local folder layout at '~/models/'.

3. Wake up all 12 cores and lock them at maximum frequencies:
   sudo nvpmodel -m 0 && sudo jetson_clocks

4. Clear any old lingering local ports:
   sudo pkill -f llama-server

5. Open a terminal right next to the 'docker-compose.yml' file and pull up:
   docker compose up -d

   (Docker will instantly stream down your clean compiled image layers from 
   the cloud, establish the hardware networks, and boot the backend flawlessly!)

6. Pass your active host console keyboard hooks into the running agent container:
   docker attach vla_docker-vla-agent-1

7. Press the [SPACEBAR], speak your command to your BRIO mic, and hit SPACEBAR again!
